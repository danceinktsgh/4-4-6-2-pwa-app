# auto_calculation_design.md｜不增加填寫負擔的自動計算設計

> 版本：v0.1（2026-10-15）｜搭配《資料串接矩陣_給資訊室_v0.1.xlsx》

## 一、核心原則

1. **只用臨床本來就要記錄的資料。** 給藥執行、生命徵象與評估、設備紀錄、入出轉、輸血、醫囑都已經在系統裡；**不為了算燈號而新增欄位。**
2. **系統預設帶入，小組長只改例外。** 系統在交班前自動算出每床的建議燈號；小組長同意就不必動作，不同意時才修改並選原因。
3. **用「已執行」，不用「有開醫囑」。** 醫囑只作為輔助資料。
4. **規則存在規則表，不寫死在程式裡。** 由護理部維護並保留版本紀錄，條件修改時不必重寫程式。
5. **唯一新增的填寫是交班一鍵自評。** 放在既有的交班或簽退畫面，幾秒鐘完成。

## 二、每班的流程

| 時間 | 系統做什麼 | 人做什麼 |
|---|---|---|
| 交班前 30 分鐘 | 依快照判定每床建議燈號，算出當量床數、負荷指數、需要人數 | 無 |
| 交班時 | 在派班畫面顯示建議燈號與觸發的規則（例如「黃：CRRT」） | 小組長確認；不同意才修改並選原因 |
| 班內 | 事件發生時自動升級並記錄時間，例如 1 小時內輸 3 單位紅血球、新入院、外出 | 無；如有需要可修改 |
| 下班時 | 彙總本班資料 | 護理師一鍵自評 |
| 每月 | 自動產出月報：負荷指數、紅燈人日、缺人班數、修改原因統計、自評平均、資料完整率 | 護理長檢視 |

## 三、哪些可以自動、哪些不行

| 自動化程度 | 項目 |
|---|---|
| **自動** | 升壓與強心藥（持續輸注品項）、ECMO 等設備、CRRT、呼吸器、輸血、新入院與術後回室、移植或重大手術術後天數、隔離；病房的入出轉人次、給藥次數、檢驗、早期預警分數、快速反應小組呼叫、評估分數、上班人數 |
| **半自動**（系統建議，小組長確認） | 急救（常事後補登）、外出（需實際離開時間）、躁動譫妄（需 RASS 或 CAM-ICU 是常規評估）、俯臥與翻身困難（以姿勢紀錄與體重代替）、臨終照護、燒傷 TBSA 與換藥 |
| **人工** | 家屬陪伴時間、照顧的實際困難度 → 用小組長修改原因和交班自評補足，**不另開欄位** |

## 四、分階段做法

| 階段 | 做法 | 護理師負擔 |
|---|---|---|
| 0（現在） | CCU 依海報人工判燈 | 小組長每班判燈 |
| 1（約 1–2 個月） | 資訊室每天撈資料，產出「建議燈號清單」；和 CCU 人工判燈並行比對一致率 | 不增加（CCU 本來就在判燈） |
| 2 | 把建議燈號放進派班或交班畫面，改為「預設帶入、例外修改」 | 比現在更少：從「每床判斷」變成「只改例外」 |
| 3 | 推廣到其他加護單位與內外科病房，接上儀表板與月報 | 只有交班一鍵自評 |

**第 1 階段的並行比對很重要。** 它能證明自動判定和臨床判斷一致，也能找出規則漏掉的情境；而且因為 CCU 本來就在人工判燈，不會增加任何人的工作。

## 五、要先確認的事（請資訊室與護理部回答）

1. 升壓藥是否透過輸液幫浦或給藥系統記錄「開始與停止時間」？停止輸注有沒有即時記錄？
2. ECMO、CRRT、呼吸器的參數是否每小時登錄在系統的流程表中？
3. 加護病房是否常規評估 RASS、CAM-ICU？是結構化欄位嗎？
4. 輸血有沒有「開始輸注時間」的紀錄？
5. 燒傷 TBSA、換藥處置是否為結構化欄位？
6. 交班或簽退畫面能不能加一個單選題？
7. 資料可否以單位、班別彙總後提供給護理部，不含病人個資？

## 六、風險

| 風險 | 對策 |
|---|---|
| 紀錄延遲或補登，使燈號偏低 | 快照時間設在交班前；小組長可修改；月報呈現資料完整率 |
| 紀錄習慣不同，單位間不可比 | 先檢查完整率；條件共識後再跨單位比較 |
| 為了多算人力而多記錄（灌分） | 規則以臨床必要紀錄為主；定期抽查；修改原因要選理由 |
| 資訊室人力有限 | 先做第 1 階段的每日報表（不需改畫面），證明價值後再排入系統開發 |
